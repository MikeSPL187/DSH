1. Рынок

Публичных разборов мобильных интерфейсов AI-приложений мало, и большая часть источников вторична. Ниже отмечено, что подтверждено источником, а что — мой разбор приложений.

ПродуктЧто сильноеЧто слабое
ClaudeСпокойный экран: приветствие по времени суток, поле ввода по центру и внизу, анимированный логотип во время ответа. Интерактивные приложения и графики прямо в чате[2]. Меню слева, выбор модели сверху[1].Два значка микрофона, неочевидные «+» и волна голосового режима, названия моделей без пояснений, «призрак» для приватного чата не объясняет себя[1].
ChatGPTМинималистичный белый экран, единая точка входа для текста, голоса, камеры и файлов, явные состояния: ожидание, поток, инструмент, готово[3]. Тестируется компактное меню вложений[4].Меню вложений из одних значков прячет возможности[3]; новое компактное меню медленнее для опытных пользователей[4].
GeminiПоле ввода стало листом снизу, который сливается с клавиатурой; выбор модели переехал в него[5].Слои различаются только тенью; меню «+» тоже лист — много листов подряд.

Termux, Blink ShellСтрока служебных клавиш (Esc, Tab, Ctrl, Alt, стрелки), «залипающие» модификаторы, жесты между сессиями[7].Это терминалы, а не агенты: нет чата, файлов и одобрений.

Платформенные тренды

  • Apple Liquid Glass (iOS 26). Управление — отдельный стеклянный слой над контентом; панели уменьшаются при прокрутке, чтобы отдать место содержимому; стекло двух видов, обычное — для навигации и кнопок[8].
  • Material 3 Expressive (Android 16). Движение на пружинах (жёсткость, затухание, скорость) вместо кривых Безье; две семьи пружин — пространственные (позиция, размер) и эффектные (прозрачность, цвет)[9]. Рекомендуют не больше 1–2 «героических» моментов на сценарий и уважать системное отключение анимаций[9].
  • Пружины Apple. Пресеты smooth (без отскока), snappy (лёгкий), bouncy (заметный)[10]. Ориентиры сообщества: отклик около 0,3 с для быстрых действий и 0,5 с по умолчанию, затухание 0,75–0,95[10].

Паттерны агентного интерфейса

  • Карточка вызова инструмента в три фазы: объявление, выполнение, результат; повторные вызовы сворачиваются со счётчиком[11].
  • Одобрения по уровню риска: чтение без вопроса, запись — один раз на область с «всегда разрешать», удаление — каждый раз и другим видом диалога[11].
  • Итог «сначала изменения»: список файлов с +/− до текста; плюс блок «проверено / предположено / не сделано»[11].
  • Фоновые задачи с индикатором в навигации, который меняет цвет, когда нужен ответ[11].
  • Кнопка «Стоп» на виду во время ответа; поле ввода не перекрывает последнее сообщение — самая частая ошибка мобильных AI-чатов[12].

2. Выводы для DSH

  1. Экран чата — главный. У лидеров всё вращается вокруг одного поля ввода. У нас оно перегружено: папка, режим, модель, запись, статистика токенов в четыре строки.
  2. Агент на телефоне без компьютера — наше уникальное преимущество. Claude Code и Codex на телефоне — пульты; у нас Host, файлы и терминал живут на устройстве. Дизайн должен это показывать, а не прятать в правой панели.
  3. Работу агента нужно показывать понятным языком: шаги, файлы, изменения, одобрения по риску. Сейчас это «Готово за 0 с» и сырые тексты.
  4. Премиальность — это движение и тишина, а не украшения: пружинные переходы, общий элемент между экранами, тактильный отклик, панели, уступающие место содержимому.
  5. Технические экраны (запуск Host, rootfs, плагины) — это первое впечатление. Сейчас пользователь видит логи proot. Нужны человеческие состояния с подробностями «под капотом» по запросу.

3. Позиционирование

DSH — карманная рабочая станция с AI-агентом. Разговаривает как лучший ассистент, работает как IDE: проект, файлы, терминал и агент в одном приложении, офлайн-ядро прямо на телефоне, безопасность по умолчанию.

Шрифты (кириллица — обязательна)

  • Golos Text — текст интерфейса и сообщений: создан для экрана и русского языка, спокойный и читабельный. Этот отчёт набран им.
  • Geologica — заголовки: геометричный, с характером, хорошо держит кириллицу.
  • JetBrains Mono — код и терминал: лучший моноширинный с кириллицей, лигатуры.

Альтернатива — системный Roboto/Google Sans Flex: меньше размер APK, меньше индивидуальности.

6. Дизайн-система

  • Цвет: 10–12 семантических токенов (фон, поверхности 1–3, текст 1–3, линия, акцент, успех, внимание, ошибка) × светлая и тёмная тема; контраст текста не ниже WCAG AA (4,5:1).
  • Типографика: шкала 12 / 13 / 15 / 17 / 20 / 24 / 32; текст ответа 16 с межстрочным 1,55; учёт системного размера шрифта.
  • Сетка: шаг 4 dp; поля экрана 16 / 20 dp; зоны касания не меньше 48 dp.
  • Форма: радиусы 10 / 16 / 24 / полный; карточки только там, где это отдельный объект (инструмент, файл, одобрение).
  • Глубина: 3 уровня (контент, плавающее управление, листы и диалоги); в тёмной теме — светлее поверхность вместо тени.
  • Иконки: единый набор с одной толщиной линии 1,75; заполненный вариант для активного состояния.
  • Тактильный отклик: лёгкий — выбор, средний — отправка и одобрение, «тик» — переключатели; выключается в настройках.

7. Анимация

Наведите или нажмите на карточку, чтобы увидеть характер пружины.

Плавнаязатухание 1,0 · отклик 0,45 с

Переходы между экранами, листы, появление ответа

Быстраязатухание 0,85 · отклик 0,3 с

Кнопки, чипы, переключатели, меню

Живаязатухание 0,7 · отклик 0,5 с

Только «героические» моменты: отправка, готово, одобрено

  • Правило: всё движение — пружины (в Compose — spring(dampingRatio, stiffness)), прерываемые жестом без рывков.
  • Связность: общий элемент между экранами (сессия → чат, файл → предпросмотр, карточка плагина → страница).
  • Поток ответа: текст появляется мягким проявлением слов, без мигающего курсора; высота сообщения растёт пружиной.
  • Сдержанность: не больше двух заметных моментов на сценарий; при системном «без анимации» — мгновенные переходы.
  • Производительность: 60/120 кадров, базовый профиль запуска, без перекомпозиции всего экрана на каждый токен.

8. Технический план

  1. Решения по направлению — ваш выбор: материал, цвет, навигация, шрифты. Затем — лист дизайн-системы (токены, компоненты, движение) как отдельная страница.
  2. Интерактивный прототип — HTML в рамке телефона, светлая и тёмная тема, реальные русские тексты, переходы и анимации на пружинах. Порядок: чат и поле ввода → работа агента и одобрения → навигация → первый запуск → инструменты → плагины → автоматизация → настройки.
  3. Проверка каждого макета по чек-листу ниже, минимум два прохода; не проходит — переделка до соответствия. Вы смотрите прототип на телефоне по ссылке и даёте замечания.
  4. Реализация в Compose: новая тема и токены в core/designsystem, библиотека компонентов с превью, затем экраны в том же порядке; старый UI заменяется по экрану, без «большого взрыва».
  5. Декомпозиция MainAppHost и ChatScreen (аудит F-13) — вместе с переносом экранов: каждый экран — свой файл и своё состояние.
  6. Проверка в приложении: скриншот-тесты Robolectric для каждого экрана в обеих темах, прогон на эмуляторе, замер плавности (пропущенные кадры), TalkBack и крупный шрифт.

9. Как проверяется каждый макет

КритерийЧто проверяется
Задача за 3 секундыГлавное действие экрана понятно без подписи и находится в зоне большого пальца.
ИерархияОдин главный элемент; второстепенное тише; нет двух одинаково громких кнопок.
КонтрастТекст ≥ 4,5:1, крупный ≥ 3:1, в обеих темах.
КасаниеЦели ≥ 48 dp, между ними ≥ 8 dp; ничего важного у краёв экрана и под жестовой полосой.
Длинный русский текстНадписи не обрезаются; кнопки и чипы переносятся или сокращаются осмысленно.
СостоянияПусто, загрузка, ошибка, нет сети, Host не запущен — каждое продумано.
ДвижениеПереход объясняет, откуда пришёл и куда ушёл элемент; анимацию можно прервать; есть режим без анимации.
