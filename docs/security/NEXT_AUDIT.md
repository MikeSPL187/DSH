# Продолжение аудита DSH: безопасность и стабильность

Документ для новой сессии Claude Code (другой аккаунт, чистый облачный контейнер).
Ниже — готовый промт, состояние работ, где копать дальше и как проверять.

## 1. Промт (вставить в новую сессию целиком)

```text
Репозиторий MikeSPL187/DSH — Android-клиент DSH (Kotlin, Compose, агент в Linux-контейнере proot на телефоне).
Работай в ветке claude/mobile-app-security-audit-8aocub: сначала git fetch и checkout этой ветки.
Если среда назначила тебе другую ветку — создай её от claude/mobile-app-security-audit-8aocub и пушь туда.
Отвечай только по-русски, включая короткие промежуточные сообщения.

Задача: продолжить аудит приложения — найти и исправить уязвимости и проблемы стабильности
(падения, зависания и ANR, утечки памяти, гонки, сбои на Android 8–15, потеря данных).
Предыдущие два круга аудита уже сделаны; не повторяй их, а копай глубже.

Перед началом прочитай целиком:
1. CLAUDE.md — правила проекта (язык, дизайн, безопасность в интерфейсе, git);
2. docs/security/NEXT_AUDIT.md — этот документ: что сделано, гипотезы, как проверять;
3. docs/SECURITY_FIXES_REPORT.ru.md — все прошлые находки (F-, N-, A-, D-, E-) и что осталось;
4. docs/ARCHITECTURE.md и docs/design/HANDOFF.md — устройство приложения и «грабли».

Подготовь окружение: bash scripts/cloud/setup.sh (для эмулятора — с флагом --emulator).
Сборка и тесты: bash scripts/cloud/gradle.sh test lintDebug :app:assembleDebug --continue -q.
Эмулятор: bash scripts/cloud/emulator.sh smoke (перед тестами Gradle — emulator.sh stop).

Как работать:
- Каждую находку подтверди: путь от реального входа (данные Host, агента, плагина, другого приложения,
  файла, сети) до вреда. Без пути — не исправляй, а опиши в отчёте как гипотезу.
- Исправление минимальное и в стиле окружающего кода; на каждую находку — тест, который падает
  на старом коде и проходит на новом (JVM-тест, Robolectric или настоящий процесс, как ShellCommandTest).
- Отказ — значит отказ: сбой сети или ошибка Host не должны выглядеть успехом (см. E-02, E-09).
- Не добавляй зависимости и не коммить gradle/verification-metadata.xml (lenient — только локально).
- Перед коммитом: полный прогон тестов и lint (0 падений, 0 ошибок lint), для изменений интерфейса —
  запуск на эмуляторе без FATAL. Коммить и пушь после каждого законченного блока.
- Новые находки дописывай в docs/SECURITY_FIXES_REPORT.ru.md продолжением нумерации (E-19, E-20, …),
  проблемы стабильности — тоже туда, с пометкой «стабильность». Правила для будущего кода — в HANDOFF.
- По каждому открытому вопросу, где решение за владельцем (меняется поведение для пользователя,
  удаляется функция), спрашивай владельца и давай 2–4 варианта с рекомендацией.
- В конце — короткий итог по-русски: что найдено, что исправлено, что проверить на реальном телефоне.
```

## 3. Где копать дальше

### Безопасность (гипотезы, не проверены)

1. **Данные от Host — недоверенные.** Протокол (`core/protocol`) и разборщики (`core/data/…/HostProjections.kt`,
   `ChatRows`, `Trajectory`, `parseModelProviders`) на огромных, глубоко вложенных или битых
   ответах: падение, OOM, зависание главного потока. Хорошо подходит фаззинг-тест на JVM.
2. **Мост `runtime/bridge`**: `SHOW_NOTIFICATION` от плагина может выдавать себя за «агент ждёт
   одобрения»; `SET_CLIPBOARD` пишет в буфер молча; параллельные `EXEC_*` и таймауты; что будет
   при 4 МиБ JSON в одной строке после авторизации.
3. **Установка плагинов**: `BridgeReleaseDownloader` (zipball GitHub без хэша — только TLS),
   `PluginInstallSpec`, индексы маркетплейса, зависимости npm (`postinstall` не запускаются ли?).
4. **Нативные плагины в процессе приложения** (N-02, не сделано): поверхность `PluginHostApiImpl`,
   что плагин может вызвать у приложения; одобрение (`PluginTrustOverlay`) — видно ли пользователю
   имя пакета и отпечаток, нельзя ли обмануть длинным именем.
5. **WebView** (`plugin/runtime-web`, `plugin/surface`): токен в URL (`loadSurface`), iframes
   сторонних плагинов, `postMessage` в `DshNativeBridge`, переход на `about:blank`/`data:`.
6. **Импорт и вложения** (`AttachmentImporter`, `ChatAttachment`): лимиты размера, подмена MIME,
   `content://` от чужих приложений, имена файлов.
7. **Терминал**: вставка текста с управляющими символами (в оболочку уходит `\r`/`\x03`?);
   «Объяснить» отправляет вывод в DeepSeek — нет ли там секретов (можно чистить `SecretScrubber`).
8. **Одобрения**: гонки нескольких запросов, истечение срока, режим «Сразу» по точному имени
   инструмента (регистр, префиксы MCP); что видит пользователь в полноэкранном предупреждении.
9. **Автоматизации**: путь проекта из хранилища, выполнение после перезагрузки (JobScheduler),
   уведомления с текстом ответа агента.
10. **Релизная сборка**: объединённый манифест release (`app/build/intermediates/merged_manifest`)
    — нет ли экспортированных компонентов из библиотек; `ScreenPreviewActivity` только в debug;
    правила R8 не открывают лишнего.
11. **Удалённый Host** (скрыт в интерфейсе, но код есть): сопряжение, хранение и отправка токена.
12. **Смена прав** (E-02): маршрут `/api/session/selectPermission` не проверен на живом Host —
    сверить с исходниками Host, если они найдутся в rootfs или upstream.

### Стабильность

1. **Главный поток**: файловые операции, разбор JSON, git в composition (`remember { … }` с I/O),
   `runBlocking`. Включить `StrictMode` в debug и пройти экраны на эмуляторе.
2. **Память**: неограниченные списки (сообщения сессии, блоки терминала, журнал вызовов
   инструментов, `ToolCallLog`, `BalanceLedger` — 400 снимков), большие изображения, кэш плагинов.
3. **Корутины и эффекты**: исключение в `LaunchedEffect` без `runCatching` роняет приложение;
   `GlobalScope`/`applicationScope` без отмены; повторные подписки при пересоздании.
4. **Смерть процесса и восстановление**: `rememberSaveable` для введённого текста и открытых листов,
   состояние после убийства системой в фоне.
5. **Host**: гонки запуск/остановка, `HostService` и правила foreground-сервисов Android 14+,
   Doze, повторное подключение WebSocket (D-33), что будет при `kill -9` Linux-процесса.
6. **Совместимость**: Android 8 (эмулятор `dsh26`), маленький экран 360 dp, крупный шрифт
   (`fontScale` 1.3–2.0), обе темы, RTL не нужен (только EN/RU).
7. **Миграции Room**: открытие базы старых версий, повреждённая база.

## 4. Как проверять

- Окружение: `bash scripts/cloud/setup.sh --emulator` (~10 минут). SDK — `/home/user/android-sdk`,
  SDK плагинов — рядом с репозиторием (`../dsh-mobile-plugin-sdk`, коммит из `sdk.lock`).
- Полный прогон: `bash scripts/cloud/gradle.sh test lintDebug :app:assembleDebug --continue -q`;
  итог считать по `**/build/test-results/**/*.xml` (на момент передачи — 582 теста, 0 падений).
  Ошибки lint: `grep -c 'severity="Error"' **/build/reports/lint-results-debug.xml` — должно быть 0.
- Эмулятор: `bash scripts/cloud/emulator.sh smoke` — загрузка до 15 минут, Linux не запускается
  (нет KVM): Host, чат с агентом, git и автоматизации проверяются тестами, а в отчёте —
  пунктом «проверить на реальном телефоне».
- Тесты интерфейса (Robolectric, Compose): пример — `app/src/test/.../ui/KeyCheckTargetTest.kt`;
  такие тесты исключаются из `testReleaseUnitTest` (см. `app/build.gradle.kts`).
- Имена тестов с кириллицей и `runBlocking { }` ломают имя класса лямбды — для них латиница.
- Помощники: `python3 scripts/cloud/deadcode.py` (объявления без использований),
  `python3 scripts/cloud/unusedimports.py <файлы>` (убрать неиспользуемые импорты).
- Скрипты `scripts/cloud/*` — только для облачного контейнера; `gradle.sh` включает lenient-проверку
  зависимостей локально, `gradle/verification-metadata.xml` не меняется.
