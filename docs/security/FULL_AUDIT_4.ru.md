## 2б. Своё приложение: чужой код, чужие источники и Linux внутри

Требование владельца: **приложение должно быть полностью нашим** — весь код, сборка, образы, плагины,
обновления и ключи — и максимально безопасным для программирования и общения. Сейчас это не так:
ниже всё, что приходит не от нас, и что из этого исполняется на телефоне с правами DSH.

### Linux внутри приложения: размер и безопасность

- **Размер.** Скачивается архив образа ≈ **306 МБ** (`archiveSizeBytes` в `app/src/main/assets/rootfs-manifest.json`,
  `rootfs-v1.0.11`: Debian 12 slim, Node 24, pnpm, Python 3, git, агент `@deepseek-ai/dsh@0.2.1-rc.2`,
  bridge-плагин 2.0.7). После распаковки — заметно больше; точно не измерено (в песочнице образ не скачивается
  из-за TLS-прокси), ориентир 1–1,5 ГБ — проверить в «Настройки → Хранилище» на телефоне.
- **Гарантировать безопасность образа сейчас нельзя.** Код приложения проверен (4 круга), но содержимое образа —
  нет: его собирает и публикует сторонний аккаунт, Host и агент в нём ни разу не запускались в нашей среде проверки.
- **PRoot — не песочница.** Всё в Linux работает с правами самого приложения (тот же UID): агент и любые его
  npm-пакеты/MCP-серверы выполняют команды, ходят в сеть, видят рабочую папку, а выход за rootfs (через `/proc`,
  прямые системные вызовы) даёт доступ к данным DSH — базе сессий, cookie Host, токену моста, настройкам. С «Доступом
  ко всем файлам» — и к общей памяти телефона. Подтверждение опасных команд — оценка текста команды, а не граница прав
  (см. G-04).

### План «приложение полностью наше»

1. **Свои репозитории** (организация владельца): APK, SDK плагинов, bridge-плагин, сборка rootfs, форк агента — с защищённой веткой и обязательным ревью.
2. **Воспроизводимая сборка всего**: proot/talloc из исходников, rootfs из закреплённых пакетов Debian/npm (lockfile + integrity), образ и плагины — артефакты нашего CI.
3. **Доверие только нашим ключам**: хэши образа и плагина вшиты в APK; любые удалённые обновления — только с подписью нашим ключом (ключ — у владельца, не в CI-секретах открытым текстом).
4. **Никаких «последних релизов» чужих репозиториев** во время работы приложения; обновления — вместе с APK.
5. **Изоляция Linux** (G-50) и сеть по разрешённому списку.
6. **Свой бренд и идентификатор** (G-49), свои ссылки «Что нового» / «Лицензии» / обновления.

## 2в. «Лучшее из лучших»: из чего сделано приложение и что заменить

Слоган владельца: **«DSH — лучшее из лучших»**. Правило раздела: компонент меняем, только если замена
**лучше** по безопасности, надёжности или удобству программирования на телефоне; если хуже или спорно — оставляем.
Даты поддержки — по состоянию на октябрь 2026 г.; перед заменой сверить с официальными страницами проектов.

## 3. Гипотезы (путь до вреда не подтверждён — сначала проверить)

- **H-1.** `android_clipboard_set` от плагина Host пишет в буфер молча — подмена скопированного адреса/команды.
- **H-2.** Ответ на одобрение при сбое сети (`HostEventsClient.answerForwardedEvent`): ошибка HTTP глотается, событие уже помечено отвеченным — `next` по тайм-ауту не уйдёт; нужен исходник Host, есть ли у него свой срок.
- **H-3.** Терминал: каждый кусок вывода заново строит текст всего блока (до 3000 строк) — рывки на `npm install`; число блоков и моделей вкладок (`TerminalHub`) не ограничено за время жизни процесса.
- **H-4.** Лист деталей инструмента (`ToolDetailBody`) показывает аргументы и вывод одним `Text` без предела — если Host не обрезает вывод, многомегабайтный результат подвесит интерфейс.
- **H-5.** `ProcessOutputParser`: в фазе STARTING любая строка stdout Host с адресом и токеном (в т. ч. вывод npm-плагина) переназначает порт/токен клиента.
- **H-6.** Режим инструмента ищется по точному имени: инструменты MCP с префиксом/другим регистром могут не попадать под «Выкл.».
- **H-7.** Автоматизация в фоне без открытого интерфейса: `approvalPolicy` ставится из `LaunchedEffect` экрана — без UI режимы «Сразу/Выкл.» не действуют, запросы висят 10 минут.
