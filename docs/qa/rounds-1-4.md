Полная сборка/unit-тесты предыдущего кандидата `69eb239e`: [42385697022](https://github.com/MikeSPL187/DSH/actions/runs/42385697022) **PASS**. Подписанный APK проверен [инструментами Android SDK](https://github.com/MikeSPL187/DSH/actions/runs/42387251475): package/version/source/хеши Linux совпадают, подпись соответствует релизу 1.1.3. SHA-256: `e10c643b0e64777853a6c5f73cb88756cd8efa5b565887c510171b8396904e30`.

Регрессии очереди после отказа выбора модели, отката Vault при неуспешной записи, преобразования путей проекта и обновления locale/font/orientation покрыты прошедшими unit-тестами.

Дополнительная Android-проверка [42383650312](https://github.com/MikeSPL187/DSH/actions/runs/42383650312), ревизия `075967c1`: **7 PASS на API 30**, crash buffer пуст. Проверен настоящий путь Keystore → сохранение настроек Host → авторизованный HTTP-запрос → терминальная ошибка в истории автоматизации; также подтверждён RPC к локальному Host при недоступном системном прокси. Найдена и исправлена отдельная причина отказа сохранения настроек: агрегированный `host.bundle.mjs` дублировал состояние загрузчика профиля. Android теперь запускает канонический `lib/bin.js` из того же закреплённого образа.

Production-код `138bc9a0` дополнительно устраняет гонку позднего createSession после уничтожения Activity, вложенное измерение при автопрокрутке и повторное закрытие интерфейса экраном загрузки аккаунта/плагинов после готовности Host. Для первой гонки unit-тест с задержанным RPC, уничтожением экранного scope, сохранением Settings и защитой другого/нового чата прошёл. Прокрутка использует [requestScrollToItem](https://developer.android.com/reference/kotlin/androidx/compose/foundation/lazy/LazyListState#requestScrollToItem(kotlin.Int,kotlin.Int)), планирующий следующий remeasure (Compose Foundation 1.7+).

[Фокусный Android-прогон 9738618b](https://github.com/MikeSPL187/DSH/actions/runs/42392675947) формально завершился с 14 PASS на API 30. Подтверждены настоящий scheduled fire, чтение маркера выбранного проекта, наследование модели, ошибки провайдера/read-only shell, offline/retry, IME/font1.3/landscape и сохранение активного запроса при Activity recreation. Журнал также сохранил частичный ответ после реального force-stop, а Retry завершился через Host. Однако скриншот восстановления показывал экран загрузки: одного Compose assertIsDisplayed было недостаточно, чтобы доказать фактическую видимость прерывания. Поэтому UI-часть N02 не закрывается по этому прогону. В 138bc9a0 загрузочная блокировка удалена, а тест требует устойчивой видимости причины, Retry и частичного ответа в настоящем accessibility-дереве Android. Cold-start проверка также теперь следит, чтобы Settings оставались видимыми во время прогрева Host.
