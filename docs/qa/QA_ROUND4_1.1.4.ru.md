# QA раунд 4 — кандидат DSH 1.1.4 (114)

Проверенный QA merge-коммит `28d67460e25d6ecc002dda1c81078503e087b458` содержит `d1ad335d` поверх опубликованной 1.1.3. Это регрессия кандидата PR №2. Приложен текст отчёта; его исходные screenshots, JSON и logcat в этой среде отсутствуют. Статическое подтверждение причины и прохождение написанного теста не заменяют нативное воспроизведение.

## Совместимость и доставка

Версия APK остаётся 1.1.4 / 114, PR №2 — draft. Формат backup и Room не меняются. RuntimeStatus получает необязательный stopReason, HostRuntimeManager — перегрузку stop(reason) с совместимым методом по умолчанию. AutomationActions.save сообщает успех, чтобы редактор не закрывался после отказа. Новые ошибки Host имеют стабильный код `dsh/auth/expired`; повтор prompt остаётся явным действием пользователя. HostRequestException сохраняет код ошибки в Result API, чтобы фильтр текста не превращал сообщение об авторизации в сетевую ошибку.

Исправление passwd/group применяется APK к уже установленному rootfs при следующем запуске. curl, Android subprocess owner и исправления агента требуют нового rootfs; простой APK со старым rootfs-v2.0.0 их не доставляет. Манифест кандидата 1.1.4 закрепляет готовые образы rootfs 2.0.2 из успешного CI `42145348410`, исходники `1cc61d57`. Сборка и dpkg install/postinst/purge прошли на x86_64 и ARM64. CI сверяет все 5708 source-файлов 303 пакетов и наличие Android owner, а манифест закрепляет SHA-256 итоговых архивов. Предыдущий кандидат `043dae8d` подтвердил source overlay, но нативная проверка затем выявила отдельное ограничение libc creat; использовать для финального dpkg-прохода нужно образ `1cc61d57`. Стабильный app-v1.1.3 остаётся без изменений. До утверждения публикации rootfs-v2.0.2 новый кандидат проверяется с локальным архивом, совпадающим с закреплённым SHA-256; публичная онлайн-установка нового образа станет доступна после публикации assets. Выпуск APK должен следовать за rootfs, а не опережать его.

Android owner даёт отмену наблюдаемых потомков с защитой от повторного использования PID. Это не kernel containment: быстро отделившийся потомок между сканированиями может остаться ненаблюдаемым. На Android этот предел проверяется отдельно; чужие процессы не завершаются ради очистки.

## Проверки

Продолжение проверки выявило дефект упаковки: в кандидате `d83f95f3` заменялся только CLI (`replaced 1`), а hoisted `@deepseek-ai/*` оставались из npm. Старый `find node_modules -path '*/node_modules/…'` не совпадал с корневыми зависимостями. Этот кандидат нельзя использовать для подтверждения исправлений агента. Обход теперь обрабатывает все уровни node_modules; source overlay ставится после npm prune, контрольные суммы итогового production-дерева проверяются и включаются в SBOM. Регрессия проверяет hoisted/nested пакеты, сохранение lockfile metadata и обнаружение подмены опубликованным кодом. CI дополнительно устанавливает и удаляет Debian-пакет с postinst через PRoot на обеих архитектурах.

Добавлены Compose-проверки замены ключа через Done/Save и ожидания проверки, а также отдельный instrumentation-тест с настоящей IME и касанием Save по экранным координатам; наследования/неоднозначности модели; сохранения выключенного Terminal; возврата в приложение до отложенного stop; сохранения Debian accounts; обновления Host cookie без второго prompt; Android process identity, TERM/KILL и освобождения TCP-порта. Итоги каждого фактического прогона и ссылки CI фиксируются в артефактах с точной ревизией.

Нативный проход: API 30 и 33+, Replace key/Continue/Show, RU↔EN и rotation во время запроса, Settings/Plugins, реальное наступление времени при Wi-Fi/зарядке, offline→online, dpkg и установка пакета в proot. Gradle и эмулятор работают раздельно. Физическая производительность не оценивается по SwiftShader. Реальный ключ в логи, screenshots полей и XML не записывается.

## Фактические нативные проверки продолжения

[API 30/33, KVM](https://github.com/MikeSPL187/DSH/actions/runs/42142928087): настоящая IME и физическое касание Save сохраняют точный проверенный ключ, a11y остаётся masked. Установка Linux и Host, Graphite и system bars, два RU/EN цикла с удержанием Appearance, rotation, Plugins → Back → Settings и Host → Terminal прошли на обеих API. Crash buffers пусты. На этом этапе package-probe выявил настоящий ENOSYS в dpkg-deb; этот прогон не является успешной приёмкой dpkg.

[Rootfs с creat-compat](https://github.com/MikeSPL187/DSH/actions/runs/42145348410) собран для x86_64 и ARM64. Регрессия воспроизводит Android ENOSYS с seccomp-фильтром и проверяет совместимый creat/creat64, umask, truncation и errno; PRoot install/postinst/purge также прошёл на обеих архитектурах. Манифест APK и native workflow используют именно этот неизменённый архив. Временный preload для диагностического прогона в итоговом сценарии отсутствует.

Окончательные APK, device evidence и результаты повторной проверки закреплённого образа указываются в [PR №2](https://github.com/MikeSPL187/DSH/pull/2). Native IME-тест также проверяет Show/Hide в настоящем a11y-дереве. Для пакетов проверяются не только первая установка и purge, но и upgrade поверх существующего файла. Публикация образа и APK в этот проход не входит.

После исправления creat нативный проход воспроизвёл второй отказ: dpkg успешно распаковал пакет и выполнил postinst, но hardlink резервной копии `/var/lib/dpkg/status-old` вернул Permission denied. Для Host включена эмуляция PRoot link2symlink. Node-публикация Host теперь сразу использует COPYFILE_EXCL, сохраняя источник и отказ при существующей цели до входа в эмулятор; это предотвращает прежний ENOENT на FUSE. Регрессия выполняет точный preload APK с имитацией разрушающего link и проверяет sync/callback/promise/ESM. Нативный сценарий дополнительно проверяет публикацию файлов в `/workspace` и dpkg upgrade.
