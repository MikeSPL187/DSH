# DSH 1.1.0 — разбор отчёта QA и исправления

Источник: независимый QA-отчёт «Подробный отчёт о тестировании DSH» от 29.10.2026 (архивы `DSH_QA_PART_01…04`,
24 карточки). Основа исправлений — исходники тега `app-v1.1.0` (`14c8b51`). Для 1.1.0 в отчёте 15 карточек
(P1: 8, P2: 7); DSH-16…DSH-24 относятся к старой основной ветке и в 1.1.0 уже исправлены или неприменимы.

## Как проверялось

- **Настоящий Host.** Опубликованный `rootfs-v2.0.0` (x86_64, SHA-256 `9a8bde2a…34578a` совпал с релизом)
  распакован, его Node Host (`@deepseek-ai/dsh@0.2.1-rc.2`) запущен на `127.0.0.1` с отдельной пустой
  `DSH_HOME`. Каждый вызов приложения (≈70 методов) сверен с дескрипторами Host: Host сам называет
  недостающие и лишние аргументы (`gateway/arguments-invalid`). Так найдены и дефекты сверх отчёта.
- **Живые тесты** `LiveHostContractTest` (запуск — переменная `DSH_LIVE_HOST` с адресом запуска Host):
  список сессий, смена прав, «Стоп», сквозной чат через свой провайдер на локальной OpenAI-совместимой
  заглушке (платные API не вызываются). На коде 1.1.0 они падают, после исправлений проходят.
- **Регрессионные тесты** на каждую карточку (протокол, данные, Robolectric/Compose, файлы, копии).
  Каждый проверен и на исходном коде 1.1.0: там он падает.
- Полный прогон `test lintDebug :app:assembleDebug` (см. раздел «Итог прогона»).

## Найдено сверх отчёта (настоящий Host)

- **«Стоп» не останавливал агента.** `session/cancel` слал `{sessionId}` вместо `{request: {sessionId}}` —
  Host отвечал `arguments-invalid`. Исправлено, проверено живым тестом.
- **Команда агента, задачи и автоматизации Host** (`TeamClient`) шли на `POST /api` без `rpcId` — всегда 404,
  экран команды агента был пуст. Маршруты и аргументы исправлены.
- **Закрепление и архив сессий не отражались** в меню: Host присылает `pinnedSessionIds`/`archivedSessionIds`
  в `workspace/follow`, приложение их игнорировало. Теперь отметки синхронизируются с Host.

## DSH-16…DSH-24

DSH-16…DSH-22 исправлены в 1.1.0 (повторные QA-тесты на теге проходят). DSH-23 — verification metadata
в 1.1.0 исправлена. DSH-24 — каталога `test-plugin` в 1.1.0 нет.

## Что не проверено

Нет ARM64-телефона и KVM: интерактивный путь на устройстве (proot внутри Android) не проходился — под
эмулятором без KVM PRoot не работает (ограничение ptrace в TCG). Host проверен как Linux-процесс из того же
rootfs, что ставит телефон.

# Второй прогон QA (`DSH_QA_ROUND2`)

QA проверил коммит `ac83f0c`: 14 из 15 карточек закрыты, DSH-13 — частично, и открыл 5 новых карточек.
Все пять подтверждены: оригинальные тесты QA второго прогона на коде `ac83f0c` дают те же 6 отказов, что
в отчёте, после исправлений проходят.

| ID | Причина | Исправление |
|---|---|---|
| R2-01 P1 | Правило `NAME=значение` в очистке копии съедало закрывающую кавычку JSON-строки: `{"note":"OPENAI_API_KEY=…","sessionId":…}` превращался в битый JSON и восстанавливался битым | `BackupSecrets` учитывает формат: JSON-файл разбирается и чистится по дереву и записывается заново (всегда валидный JSON); строки JSONL — так же построчно; в строках-фрагментах JSON значение без кавычек обрывается на `"`/`\` |
| R2-02 P2 | Очистка шла построчно: поле `apiKey` с переносом строки после `:` не находилось; у `NAME="a b"` удалялось только первое слово | Разбор JSON по дереву находит поле при любом форматировании; значения в кавычках (`"…"`, `'…'`) удаляются целиком. Файлы без секретов по-прежнему копируются байт в байт |
| R2-03 P2 | Наборы «закреплено/в архиве» из `workspace/follow` применялись UPDATE-ом; если строки сессии в кэше ещё не было, они терялись | При вставке строки применяются последние наборы Host (только для того Host, чьи кадры получены) |
| R2-04 P2 | `team/listTasks` в Host нет (404), клиент возвращал `Success(пусто)` | Отказ маршрута, `ok: false`, битый ответ — `Failure`. Так же исправлены `getAgentTeam` и `getAutomationTasks` (отказ Host раньше превращался в «команды нет»/«автоматизаций нет») |
| R2-05 P2 | `accountRpc` не проверял `result.ok`, ответ без `status` разбирался как `signed-out` | Успех — только при `ok: true`; ошибка Host возвращается с её кодом; состояние без `status` — ошибка разбора, а не выход из аккаунта |

**Ограничение очистки копий.** JSON-файл больше 16 МБ разбирается построчно: поле-секрет, разнесённое на
несколько строк, в таком файле не находится (ключи известного вида — `sk-…`, `ghp_…` и т. п. — находятся).

**Замечание к тесту QA `freshCacheRetainsFlagsWhenBaselineArrivesBeforeSessionRows`.** На нашем стенде он,
оказавшись первым в JVM, не укладывается в свой таймаут 5 с из-за холодного старта Robolectric и SQLite;
с таймаутом 60 с проходит на исправленном коде и падает на `ac83f0c` с исходным сообщением QA. Тот же
сценарий в репозитории — `SessionFlagsRoomTest`.
