# DSH Mobile 1.0.6 — исправления по аудиту: технический план и отчёт

Ветка: `claude/mobile-app-security-audit-8aocub`. Базовая версия: исходники тега
`app-v1.0.6` (upstream-коммит `72c35d2`, 834 файла, коммит `857d9a2` в этой ветке).
Загруженный APK сверен: SHA-256 `d97476013f80…e016588b3` совпадает с проверенным в аудите релизом.

## 1. Как проверялось

- Установлены Android SDK 35 и JDK 21, проект собирается целиком (`:app:assembleDebug`)
  вместе с Native UI SDK (composite build).
- Выполняется весь набор unit-тестов (`./gradlew test`): **296 тестов (debug + release), 0 падений**.
  До исправлений в релизе 1.0.6 один тест падал (`SlotCoverageTest`): CI собирал APK, но тесты не запускал.
- Добавлено 9 новых тестовых классов, около 60 тестов. Они воспроизводят сценарии из аудита:
  неверный semver, `../` в имени пакета, откат обновления, zip/tar-ссылки, подмена дайджеста,
  DoS моста, сопряжение без токена, неверный TLS-отпечаток.
- Последний прогон: **194 теста в debug-варианте и JVM-модулях, 0 падений** (плюс Robolectric-галерея
  экранов и тест запуска под Android 8.1).
- **Прогон на эмуляторе Android 8.0 (API 26, x86_64, русская локаль).** Пройдены онбординг, чат,
  отправка без Host, выбор модели и режима, боковое меню, правая панель (файлы, предпросмотр,
  терминал, браузер), магазин плагинов с реальной загрузкой и установкой APK, диалог доверия
  native-плагина (TOFU), все разделы настроек, смена языка, удалённое подключение, выход и
  перезапуск. Падения ловились через `logcat -b crash`, зависания через дампы потоков.
- **Ограничение стенда.** В облачной VM нет KVM, эмулятор работает в режиме TCG. Под ним PRoot
  падает (`IS_IN_SYSENTER(tracee)` — ограничение ptrace в QEMU TCG, не дефект приложения), поэтому
  функции, которым нужен работающий Host (ответы агента, сессии, автоматизация), на эмуляторе
  не проверены. Они покрыты unit-тестами и требуют реального телефона.

## 3. Статус по каждой находке аудита

### P0 — блокирующие

| ID | Что было | Что сделано |
|---|---|---|
| **N-01** | `discovery.scan(pinnedFingerprints = emptyMap())`: проверка подписи фактически отключена | Новый `NativePluginTrustStore`: pluginId привязывается к паре (packageName, SHA-256 сертификата), которую **явно одобрил пользователь**. Впервые найденный плагин получает статус `UNTRUSTED` и не загружается. Другой пакет или подписант с тем же pluginId получает `SIGNATURE_MISMATCH` и тоже требует повторного одобрения. APK с несколькими подписантами отклоняются. |
| **N-02** | Код companion-APK загружался в процесс приложения автоматически | Загрузчик вызывается только для `READY`, то есть одобренных плагинов. Перед загрузкой подпись перечитывается из системы (закрыто окно TOCTOU между сканированием и загрузкой). Отдельный sandbox-процесс не реализован: это архитектурное изменение SDK-контракта. |
| **N-03** | JS-пакет из манифеста APK ставился автоматически при каждом пересканировании | Автоустановка удалена. JS-пакет ставится один раз, в момент одобрения, и его источник показан в диалоге. |

В диалоге одобрения видны pluginId, имя пакета, полный отпечаток сертификата и связанный JS-пакет.
Там же предупреждение, что плагин получает все права приложения. Для изменившейся подписи
показывается отдельное предупреждение.

## 5. Что остаётся и рекомендации

1. **Прогнать на устройстве** сценарии T01–T12 и матрицу из 18 пунктов аудита. Особенно:
   первое одобрение native-плагина после обновления (все ранее загружавшиеся companion теперь потребуют подтверждения),
   обновление rootfs при нехватке места и kill во время установки,
   работу Host после `stopWithTask=false`.
2. **Поведенческие изменения, о которых стоит знать:** удалённый Host и источники маркетплейса только по HTTPS
   (или `http://127.0.0.1` через SSH-туннель); companion-плагины загружаются только после одобрения.
