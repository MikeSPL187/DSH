# DSH — правила работы

## Общение
- Всегда отвечать на русском языке.
- Запускать и проверять приложение самостоятельно (эмулятор, сборка, тесты), не перекладывать это на владельца.
- По каждому открытому вопросу спрашивать владельца и давать варианты на выбор.

## Требования к дизайну (главное)
Делаем лучшее мобильное приложение для общения и программирования.

- Дизайн: красивый, удобный, эффективный, чистый, информативный и функциональный.
- На каждом экране есть всё необходимое для задачи этого экрана.
- Каждая деталь и мелочь продумана: пустые состояния, ошибки, загрузка, длинные тексты, обе темы, маленький экран.
- Весь функционал и дизайн, нужный для общения и программирования, должен быть.
- Премиальный уровень в духе Apple, но не копия: плавные пружинные анимации, единая система.
- Экраны выглядят как части одной системы: те же токены, сгруппированные блоки, шапка «Назад», листы.
- Дизайн-система: темы «Фарфор» (светлая) и «Графит» (тёмная), акцент индиго,
  шрифты Golos Text / Geologica / JetBrains Mono.

## Как проверять каждый макет
Каждый макет проверяется несколько раз, пока не будет без замечаний:
1. Скриншоты всех состояний: светлая и тёмная тема, обычный и узкий (360 px) экран, сценарий до конца.
2. Автоматический аудит: контраст текста по WCAG AA (4,5:1, крупный 3:1),
   касаемые зоны не меньше 40 px, обрезанный текст, ошибки JavaScript.
3. Поиск улучшений, а не только ошибок: чего не хватает экрану для его задачи.
4. Повторный прогон после правок и регрессия по всем остальным экранам
   (новые CSS-классы не должны пересекаться со старыми).
